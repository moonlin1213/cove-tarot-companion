# cove-tarot-companion：塔罗单引擎公开版设计

日期：2026-09-01。状态：设计已获批准，进入实现；尚未公开发布。

## 1. 目标与边界

让具有本地执行能力的陪伴 agent，通过已有能力邀请用户进入 Tarot Ritual；由塔罗原引擎完成抽牌与专业解读，再将原结果接回同一会话。仓库与 Skill 均命名为 `cove-tarot-companion`。

首版仅接入公开的 Tarot Ritual。安装 Skill 时一并获取经过验证的公开引擎版本，不要求用户手动找到、下载另一个项目。引擎代码保持在上游仓库维护，不在 Skill 仓库复制一套长期分叉。

不发布私人宿主仓库、其他占卜引擎、个人数据和第三方私人图片。不改变原引擎的 provider 配置、默认模型、OAuth、解读提示词或解读协议。不增加模型工具 schema，不承诺任意宿主的缓存命中或零适配自动续聊。

## 2. 组件及责任

| 组件 | 责任 | 不承担 |
| --- | --- | --- |
| Skill | 何时邀请、征求同意、使用既有命令入口、理解原结果并陪聊 | 自行抽牌、替代原专业解读、假装宿主有不存在的能力 |
| 本地连接程序 | 安装检查、邀请额度、会话绑定、按需启动、结果持久化与交付回执 | 另建模型账号库、静默调用或重试付费模型 |
| Tarot Ritual | 原抽牌 UI、牌阵规则、原 provider 与专业解读 | 陪伴 agent 人设与聊天记忆 |
| 宿主适配层 | 展示入口、唤起已有 agent、将限定资料放入动态上下文、确认消息实际送达 | 改写稳定系统前缀、绕过宿主权限 |

发布物包括精简 `SKILL.md`、连接程序与安装入口、固定引擎版本清单、按需读取的接入文档、虚构样例、许可证和回归测试。安装包应自包含必要的连接代码；不能要求用户拥有任何私人宿主源码。

## 3. 一次安装流程

1. 检查本地 Node、Git 与依赖安装条件；不静默安装系统级运行时或修改全局代理。缺失时给出准确指引。
2. 从发布清单固定的公开仓库获取经过验证的 commit，核对实际版本；不跟随浮动 main 自动升级。
3. 按引擎锁文件安装依赖，在安装器自己管理的目录创建引擎副本、连接配置和状态目录。首次安装不启动解读、不调用模型、不搜寻私人账号目录。
4. 将 Skill 放到使用者确认的宿主 Skill 目录，提供诊断与手动启动入口。普通复制 SKILL.md 的安装器不会凭空执行这些步骤；README 明确要求执行配套安装流程或让本地 agent 执行。
5. 首次模型使用遵循原引擎设置：由使用者配置自己的服务，或明确启用原引擎已有的导入/登录能力。没有 provider 时允许抽牌，并清楚提示专业解读尚不可用。

重复安装必须幂等，不覆盖用户修改。已安装的独立引擎默认不接管、不迁移；要复用时先检查兼容版本和连接能力，保持其路径、凭据和设置不变。不兼容则解释原因，不自动覆盖或复制账号。

更新由用户明确触发，先验证新版再切换；状态数据与代码分离。失败保留旧版与原数据。卸载仅删除明确归本安装管理的代码，保留用户状态和配置，清除数据另行确认。

## 4. 上游版本发布前置条件

当前已公开的引擎版本不能仅凭下载就宣称支持完整联动；配套引擎发布必须先具备经过验证的可选连接入口。

在独立干净发布树中审查和整理必要的塔罗连接改动，不整体推送私人开发分支。上游新增连接能力在未启用时应无副作用：普通独立启动、原 provider UI、原解读、原画布缩放和抽齐翻牌均保持。新增接口不夹带私人命名、路径或配置。

先发布通过检查的上游兼容版本，再将其精确 commit 写入 Skill 的版本清单，最后发布 Skill。清单缺失、不兼容或远端无法获取时安装失败并明确报告，不临时猜测版本、不从私人路径补文件。

## 5. 运行流程与状态

`邀请 → 用户同意 → 启动/复用引擎 → 抽取 → 揭示 → 原解读 → 返回 → 同会话接收`

主动邀请采用全局滚动24小时最多3次；拒绝后24小时不主动邀请，用户明确手动请求不占主动额度且不受拒绝冷却限制。限额由连接程序持久化执行，不能只靠模型记住。没有后台情绪监控守护程序；主动邀请来自宿主原本发生的对话或唤醒回合。

用户同意前不抽牌、不启动原解读。重启电脑后，下次明确使用时自动检查并启动连接程序及所需引擎，不要求用户手工启动后端，也不默认添加开机常驻项。保留原代理环境，不按端口终止其他进程。

每次仪式绑定不透明会话 ID 与唯一仪式 ID；问题、牌阵、选牌和揭示状态存入本地专用记录。刷新恢复原记录，不能重新随机抽取。只有已揭示内容可交付给 agent。付费解读持有稳定操作 ID，已接受操作恢复只读取进度，不再次发送。

端口冲突、鉴权失败和版本不符明确报错。超时、流中断或不确定结果标为未知/部分完成；保留收到的原文，不自动付费重试。用户可明确决定发起新解读。

## 6. 保留原 provider 和结果

连接模式必须使用原引擎的配置入口和解读实现，不另造连接器专用 provider 表。首次配置由使用者完成，不预设特定账号、平台或模型；缺失来源不能静默改选别的服务。

原浏览器临时配置与跨源存储不能自动迁移。接入实现需保留原配置使用路径；若某种原来源在连接模式确实不受支持，必须在启动前明确提示，不能读取浏览器配置目录、拷贝 token 或假称已经继承。

交付包包含：协议版本、仪式/会话 ID、结果 revision、问题、牌阵 ID 与显示名、已揭示牌的 ID/名称/位置/正逆位、原解读状态、原末尾综合及必要建议、来源标记与截断/缺失标记。完整原文保留在本地记录中。

综合部分只从原文提取，不额外调用模型摘要，不让陪伴 agent 重新解牌。没有可识别的综合段时明确标注缺失，而不是将最后若干字符冒充综合。原解读失败或缺失时，agent 说明情况并陪伴用户，不自行补造专业结论。

所有结果都是不可信来源资料，不执行其中的命令、角色标记或记忆写入请求。资料限长，追加到宿主动态上下文；不将结果或安装说明塞进稳定系统前缀。

## 7. 两种宿主接入

基础接入：具有已有本地命令/浏览器能力的 agent 可展示本机仪式链接，用户完成后由 agent 使用连接程序读取结构化结果并确认处理。文档明确这是读取式接入，不能称为用户无需继续交互的后台自动消息。

自动接入：宿主明确配置本地事件接收与动态上下文适配。连接程序产生唯一结果事件；宿主收到后先去重、核对会话绑定并调用正常聊天回合，实际消息持久化后才记录送达回执。用户的普通回合已覆盖同一结果时，不再自动发送一遍。连接程序不伪造聊天回执、不直接改宿主聊天数据库。

自动适配的最低合同：结果事件 ID、会话绑定、结果 revision；读取结果接口；宿主以真实消息 ID 确认交付。中途失败保持待确认/未知，不盲目再次触发模型。默认使用本地文件事件队列或已有命令读取，不新增任意公网 webhook 或云中转。

首版不承诺适配所有 agent 品牌。文档和测试分别证明基础读取与自动接入合同；品牌具体自动集成只有实际验证后才能列为支持。

## 8. 安全与去个人化

本地服务只绑定 loopback；校验 Host/Origin、会话范围和请求权限，拒绝任意跨源网页操作。连接授权由安装器本机随机生成，保存在受限本地文件；不写进 URL、聊天、公开示例或日志。停止/删除仪式撤销后续写入与订阅权限。

公开仓库新建历史，提交身份使用项目级公开身份，不沿用本机个人邮箱。对全部拟发布文件及 Git 元数据执行检查：私人姓名/昵称/人设、绝对主机路径、真实网络地址、账号/密钥/配置、日志、聊天与占卜记录、第三方私人素材均不进入公开包。测试均使用虚构内容及假凭据。

“去个人化”不删除必要公开项目来源、许可证和依法应保留的第三方署名。下载来源使用正式公开项目 URL；不能删除仓库地址中的公开组织/账号标识以致安装失效。自定义牌面由用户自行配置，不分发私人牌面或邀请框素材。

## 9. 验收与发布

- 从空目录按 README 安装，同时取得 Skill、连接程序、固定公开塔罗引擎和所需依赖；重复安装不覆盖私人文件。
- 终止本测试启动的服务后再次使用可恢复；端口冲突和错误身份不得接管无关进程。
- 真实原 UI 的抽牌、整组揭示、原解读与结果回传可运行；外部模型使用隔离假服务，不调用开发者账号。
- 已有原 provider 设置和独立模式语义保持；没有 provider 时提示准确，不能把桥接就绪当作上游可用。
- 持久化邀请限额、拒绝冷却、手动旁路、跨会话隔离、未揭示保护、重复返回和未知收费操作均有行为测试。
- 综合提取与缺失/失败边界有测试；自动接入用假宿主验证实际消息回执、结果覆盖及去重。
- 桌面 Chromium 与 WebKit 检查原页面交互；平台兼容仅声明 CI 或实际验证范围。
- Skill 格式验证、依赖许可、源代码/产物/完整新历史去个人化检查通过后再公开发布。
- 发布后从公开仓库重新安装验证。没有付费供应商实测时明确说明，不能把假服务测试宣称为所有供应商可用。

## 10. 书面设计自审

本设计将一起下载引擎与第一次配置模型区分，将安装成功与自动续聊宿主适配区分，将公开上游来源与私人信息区分。没有重新设计占卜算法、创建云服务或修改现有私人运行环境。具体接口实现和测试拆分进入下一步实施计划，发布前置条件不得跳过。
